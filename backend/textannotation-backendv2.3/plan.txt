Build a complete, production-ready backend for a Text Annotation / Classification System using Python FastAPI + MongoDB + Gemini Flash.
 
Do NOT build a frontend.
 
The frontend already exists and will send either:
 
1. Direct text entered into a textarea
2. An uploaded PDF
3. An uploaded DOCX
4. An uploaded TXT file
5. An uploaded image such as JPG/JPEG/PNG
 
The user will choose one of ONLY TWO analysis types:
 
- "ENTITY_EXTRACTION"
- "SENTIMENT_ANALYSIS"
 
The backend must process the input, perform the selected analysis, return structured JSON, and save the result in MongoDB.

The API must support two input modes.
 
Mode 1 — Direct Text
 
Example:

Mode 2 — File Upload
 
Supported:
 
PDF
DOCX
TXT
JPG

Extract text from the uploaded file before performing analysis.

3. API Design
 
Create:
 
POST /api/v1/annotations/analyze
 
Use "multipart/form-data" so the endpoint can support both text and files.
 
Parameters:
 
analysis_type:
    ENTITY_EXTRACTION
    SENTIMENT_ANALYSIS
 
text:
    optional string
 
file:
    optional UploadFile
 
drug_name:
    optional string
 
Validation rules:
 
- Either "text" OR "file" must be supplied.
- Do not require both.
- Reject the request if both are missing.
- "drug_name" is required when "analysis_type=ENTITY_EXTRACTION".
- "drug_name" is not required for "SENTIMENT_ANALYSIS".
 
Example direct sentiment request:
 
analysis_type=SENTIMENT_ANALYSIS
text=The medicine worked well for me and the packaging was good.
 
Example entity request:
 
analysis_type=ENTITY_EXTRACTION
drug_name=Paracetamol
file=medicine_ingredients.pdf
 
Also support:
 
analysis_type=ENTITY_EXTRACTION
drug_name=Paracetamol
text=Each tablet contains Paracetamol 500 mg and Caffeine 30 mg.

6. ENTITY EXTRACTION — DRUG PRESENCE CHECK
 
This application's entity extraction has a specific purpose.
 
The frontend provides a drug/ingredient name.
 
Example:
 
drug_name=Paracetamol
 
The uploaded/extracted/direct text may contain:
 
Each tablet contains:
 
Paracetamol 500 mg
Caffeine 30 mg
Phenylephrine Hydrochloride 5 mg
 
The backend must determine whether the requested drug/ingredient appears in the supplied content.
 
Do NOT rely exclusively on Gemini for this.
 
Implement a deterministic-first pipeline.

7. Drug Matching Pipeline
 
Implement:
 
Extracted / Direct Text
          |
      Normalize
          |
   Exact Matching
          |
   Case-insensitive
      Matching
          |
  Normalized Matching
          |
   Fuzzy Matching
          |
 Gemini Validation
 only when required
          |
     Final Result
 
Normalization should account for:
 
- uppercase/lowercase
- extra whitespace
- punctuation
- line breaks
- OCR spacing differences
 
Example:
 
PARACETAMOL
Paracetamol
paracetamol
 
should be treated consistently.
 
Use an appropriate fuzzy matching library such as RapidFuzz.
 
Configure the fuzzy-match threshold through settings.
 
Do NOT allow a weak fuzzy match alone to produce a high-confidence medical ingredient match.

8. Gemini Entity Validation
 
Gemini should be used only when semantic validation is required.
 
Examples include:
 
- ingredient aliases
- abbreviations
- salt forms
- OCR variations
- complex ingredient descriptions
 
Gemini must NOT invent an ingredient.
 
Gemini must determine whether the requested ingredient is supported by the supplied text.
 
Require strict structured output.
 
Example response:
 
{
  "analysis_type": "ENTITY_EXTRACTION",
  "searched_drug": "Paracetamol",
  "found": true,
  "match_type": "EXACT",
  "matches": [
    {
      "matched_text": "Paracetamol 500 mg",
      "ingredient": "Paracetamol",
      "strength": "500 mg",
      "page": 1
    }
  ]
}
 
Possible "match_type" values:
 
EXACT
NORMALIZED
FUZZY
SEMANTIC
NOT_FOUND
 
If not found:
 
{
  "analysis_type": "ENTITY_EXTRACTION",
  "searched_drug": "Ibuprofen",
  "found": false,
  "match_type": "NOT_FOUND",
  "matches": []
}
 
Do not interpret "found=true" as meaning the drug is safe, recommended, equivalent, effective, or suitable for a patient.
 
It only means the ingredient appears to be present in the supplied content.
 
---
 
9. Important Medical Safety Rule
 
This system performs DOCUMENT/TEXT ANALYSIS.
 
It is NOT a clinical decision system.
 
Never generate claims such as:
 
This medicine is safe for you.
 
You should take this medicine.
 
This medicine can replace another medicine.
 
This dosage is appropriate.
 
This medicine will treat your condition.
 
Only report information supported by the supplied document/text.
 
For example:
 
Paracetamol 500 mg was detected in the supplied ingredient text.
 
is acceptable.

10. SENTIMENT ANALYSIS
 
For:
 
analysis_type=SENTIMENT_ANALYSIS
 
use Gemini Flash.
 
Example input:
 
The medicine worked well for me and the packaging was good.
 
Return:
 
{
  "analysis_type": "SENTIMENT_ANALYSIS",
  "sentiment": "POSITIVE",
  "confidence": 0.94,
  "reason": "The text expresses satisfaction with the medicine and its packaging."
}
 
Support ONLY:
 
POSITIVE
NEGATIVE
NEUTRAL
MIXED
 
Example negative input:
 
The packaging was damaged and the product did not meet my expectations.
 
Response:
 
{
  "analysis_type": "SENTIMENT_ANALYSIS",
  "sentiment": "NEGATIVE",
  "confidence": 0.95,
  "reason": "The text expresses dissatisfaction with the product and packaging."
}
 
Example mixed:
 
The medicine worked well but the packaging was damaged.
 
Response:
 
{
  "analysis_type": "SENTIMENT_ANALYSIS",
  "sentiment": "MIXED",
  "confidence": 0.90,
  "reason": "The text contains positive feedback about the medicine but negative feedback about the packaging."
}
 
Require Gemini to return structured JSON.
 
Validate Gemini output using Pydantic.
 
Do not save unvalidated Gemini output.
